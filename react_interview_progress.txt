8. useEffect
------------
Learned:
- useEffect is used for side effects
- API calls
- Updating document title
- Timers

A) No dependency array:
useEffect(() => {
  console.log("Runs after every render");
});

B) Empty dependency array:
useEffect(() => {
  console.log("Runs after initial mount");
}, []);

Note: React StrictMode in development can cause extra effect runs/logs.

C) Dependency array:
useEffect(() => {
  console.log("Current count:", count);
}, [count]);

This runs after the initial render and again when count changes.

Important understanding:
If the component has:
const [count, setCount] = useState(0);
const [name, setName] = useState("");

and:
useEffect(() => {
  console.log("Effect ran");
}, [count]);

If name changes:
- Component re-renders: YES
- Effect runs because of name change: NO

The effect runs again when a value in its dependency array changes.

Document title example:
useEffect(() => {
  document.title = "Count: " + count;
}, [count]);


9. useEffect Cleanup and setInterval
------------------------------------
Learned:
- setInterval(function, timeInMilliseconds)
- setInterval repeatedly runs code after the specified interval
- clearInterval(timer) stops the interval
- Cleanup function is returned from useEffect

Example:
useEffect(() => {
  const timer = setInterval(() => {
    setSeconds((previousSeconds) => previousSeconds + 1);
  }, 1000);

  return () => {
    clearInterval(timer);
  };
}, []);

Simple understanding:
useEffect starts the interval.
timer stores the interval ID/reference.
The returned cleanup function runs when cleanup is needed, such as component unmounting.
clearInterval(timer) stops the repeating interval.

  throw new Error("Failed to add product");
}

Important:
The POST endpoint returns one Product object.
If products state is later used with products.map(...), it must remain an array.

Wrong idea:
setProducts(data); // if data is one product object
products.map(...); // error because object does not have map()

Better:
After successful POST:
setName("");
setPrice("");
await getAllProducts();

GET example with async/await:
async function getAllProducts() {
  try {
    setLoading(true);
    setError("");

    const response = await fetch(
      "http://localhost:8080/api/getAllProducts"
    );

    if (!response.ok) {
      throw new Error("Failed to get products");
    }

    const data = await response.json();
    setProducts(data);

  } catch (error) {
    setError(error.message);

  } finally {
    setLoading(false);
  }
}

catch vs finally:
- catch runs when an error is handled in the promise/async flow.
- finally runs regardless of success or failure.

- receiveMessage = actual parent function

Flow:

-> parent function receiveMessage(...) runs
-> parent state updates


13. Lifting State Up
--------------------
Learned when two sibling components need the same shared data.

Example structure:
App
├── Search
└── ProductList

State is kept in their nearest common parent:

const [search, setSearch] = useState("");

<Search search={search} setSearch={setSearch} />
<ProductList search={search} />

Search can update the parent's state:
<input
  value={search}
  onChange={(event) => setSearch(event.target.value)}
/>

ProductList can read the same updated value:
const ProductList = ({ search }) => {
  return <h1>{search}</h1>;
};

Rule:
- Pass state value when a child needs to read it.
- Pass setter/callback when a child needs to update it.

2. useContext()
---------------
Purpose:
Share data between components without passing props through every intermediate component.

Problem: Prop drilling

App
 ↓ props
ComponentA
 ↓ props
ComponentB
 ↓ props
ComponentC

Context allows shared data to be accessed where needed.

Small example:

import { createContext, useContext } from "react";

const ThemeContext = createContext();

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Child />
    </ThemeContext.Provider>
  );
}

function Child() {
  const theme = useContext(ThemeContext);
  return <h1>{theme}</h1>;
}


3. useRef()
-----------
Main interview uses:
- Access a DOM element directly

import { useRef } from "react";

const App = () => {

4. useReducer()
---------------
Purpose:
Manage more complex state updates in a structured way.

Basic idea:
state + action
-> reducer decides how state changes
-> new state

Small example:

import { useReducer } from "react";

const reducer = (state, action) => {
  if (action.type === "increment") {
    return { count: state.count + 1 };
  }

  return state;
};

const App = () => {
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <>
      <h1>{state.count}</h1>
      <button onClick={() => dispatch({ type: "increment" })}>
        Increment
      </button>
    </>
  );
};


5. Custom Hooks
---------------
Purpose:
Reuse stateful React logic.

Hook names normally start with "use".

Small example:

import { useState } from "react";

const useCounter = () => {
  const [count, setCount] = useState(0);

  const increment = () => {
    setCount(count + 1);
  };

  return { count, increment };
};

Using it:
const { count, increment } = useCounter();


6. useMemo()
------------
Purpose:
Memoize a calculated value so React can reuse it instead of recalculating unnecessarily when dependencies have not changed.

Small example:

import { useMemo } from "react";

const total = useMemo(() => {
  return price * quantity;
}, [price, quantity]);

Interview-level idea:
useMemo remembers a computed VALUE.


7. useCallback()
----------------
Purpose:
Memoize a function reference.

Small example:

import { useCallback } from "react";

const handleClick = useCallback(() => {
  console.log("Clicked");
}, []);

Interview-level idea:
- useMemo memoizes a VALUE.
- useCallback memoizes a FUNCTION.
